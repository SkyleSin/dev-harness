# test-authoring-and-run

## Overview

이번 변경분에 대한 targeted 테스트를 만들고 실행한다. 전체 회귀는 `regression-run` 에서 다룬다. 테스트 실행 명령은 프로젝트 규칙 문서의 '명령'을 그대로 쓰며 이 스킬에는 명령을 넣지 않는다.

## Workflow

1. `{RUN_DIR}/01-design.md` 의 테스트 계획과 `{RUN_DIR}/02-implementation.md` 의 변경 파일 목록을 로드한다.
2. 대상의 기존 `tests/` 구조와 conftest 관례(fixture, marker, 배치)를 확인한다.
3. 테스트 파일을 작성하거나 편집한다.
4. 프로젝트 규칙 문서의 테스트 명령으로 **구체 파일 또는 노드 ID 만** 실행한다 (전체 X). 명령이 없으면 추측하지 않고 `blocked` 로 반환한다.
5. 결과를 아래 양식으로 `{RUN_DIR}/03-tests.md` 에 저장한다.

## 산출물 형식 (`03-tests.md`)

```md
# 03. Targeted 테스트

## 작성한 테스트 파일
| 파일 | 신규/편집 | 커버 케이스 |
| --- | --- | --- |

## 실행 명령
- `{실제 실행한 명령}`

## 실행 결과
- 총 실행: N개
- Pass: N / Fail: N / Skip: N

## 실패 케이스 (있는 경우)
| 노드 ID | 실패 요지 | 분류 (코드 이슈 / 테스트 이슈 / 브리프 애매) | 근거 |
| --- | --- | --- | --- |

## 다음 단계 권고
- targeted pass → regression-run 으로 진행
- targeted fail → reviewer 로 라우팅 (회귀 스킵)
```

## 품질 기준

- 브리프 테스트 계획의 케이스가 모두 커버된다 (정상 + 경계/실패).
- 새 테스트가 실제로 새 동작을 검증한다 (assertion 없이 지나가지 않는다).
- 실행 결과는 실제 출력 기반이며 사후 추측을 하지 않는다.
- 실패 분류는 근거(어떤 assertion / 에러 메시지)와 함께 남긴다.

## 예외와 금지 행동

- 애플리케이션 코드 파일을 수정하지 않는다.
- 실패한 테스트를 삭제하거나 skip 처리해서 통과시키지 않는다.
- targeted 가 실패한 상태에서 회귀를 실행하지 않는다.
