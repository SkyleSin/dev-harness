# design-brief

## Overview

설계 브리프는 이후 구현·테스트·리뷰가 모두 근거로 삼는 문서다. 임의로 채우지 않고, 프로젝트 규칙 문서의 규약을 지킨 최소 완결 브리프를 만든다.

## Workflow

1. `project-context-loader` 반환값을 입력으로 확인한다.
2. 아래 양식의 각 섹션을 채운다. 프로젝트 규칙 문서의 '설계 브리프 추가 섹션'을 양식 끝에 이어 붙인다.
3. 프로젝트 규칙 문서의 규약에 위배가 없는지 자체 점검한다.
4. 사용자 결정이 필요하거나 정보가 부족한 부분은 `{RUN_DIR}/decisions.md` 에 항목으로 등록한다 (양식: `.claude/docs/runs.md`). 이미 있는 항목은 중복 등록하지 않고 `[x]` 항목은 확정으로 반영한다.
5. `{RUN_DIR}/01-design.md` 로 저장한다. 질문은 설계 문서에 쓰지 않고 항목 제목으로만 인용한다.

## 산출물 형식 (`01-design.md`)

```md
# 01. 설계 브리프

## 목표
- 요청 한 문장:
- 완료 기준:

## 대상
- {TARGET}

## 변경 파일
| 파일 | 변경 유형 (신규/편집/삭제) | 요지 |
| --- | --- | --- |

## 외부 시스템 · 데이터 영향 (해당 시)
- 호출 대상 / 변경되는 데이터:
- 실패·재시도 전략:

## 테스트 계획
- 커버할 케이스 (정상 / 경계 / 실패):
- 새 테스트 파일 경로 (제안):
- fixture 요구사항:

## 미확정 항목
- (decisions.md: 항목 제목) — 가정한 권장안 한 줄

## 프로젝트 규칙 추가 섹션
- {rules.md 의 '설계 브리프 추가 섹션' 을 그대로 옮겨 채운다}
```

## 품질 기준

- 프로젝트 규칙 문서의 규약 위배가 없다.
- 변경 파일 목록은 실제 존재하는 파일 또는 신규 파일 경로로 명확하다.
- 테스트 계획에 정상 1개 이상 + 경계 또는 실패 1개 이상이 있다.
- 미확정 항목은 `decisions.md` 에 등록되어 있고, 설계에는 제목과 가정한 권장안만 적는다.

## 예외와 금지 행동

- 없는 파일 경로를 추측으로 넣지 않는다.
- 프로젝트 규칙 문서에 없는 규약을 새로 도입하지 않는다.
- 미확정 항목을 등록하지 않고 임의 결정으로 넘기지 않는다.
- `decisions.md` 의 사용자 줄(`  ->`)을 고치거나 지우지 않는다. 항목 제목은 대답할 수 있는 질문 한 문장으로 쓰고, 직접 확인할 수 있는 사실은 항목으로 올리지 않는다.
